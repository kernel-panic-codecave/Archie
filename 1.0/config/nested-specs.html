    Nested Specifications¶

    Nested specifications allow complex hierarchical configurations with reusable components.

    Basic Concept¶

    Nested specs let you create configuration structures within configuration structures, enabling:

    • Reusable configuration templates
    • Deeply nested settings
    • Dynamic configuration structures

    Creating a Nested Spec¶

    Define a spec by extending CategorySpec:

    class DatabaseConfig : CategorySpec(Component.literal("Database")) {
    val host by string(
        title = Component.literal("Host"),
        default = "localhost"
    )

    val port by int(
        title = Component.literal("Port"),
        default = 3306,
        min = 1,
        max = 65535
    )

    val username by string(
        title = Component.literal("Username"),
        default = "root"
    )

    val password by string(
        title = Component.literal("Password"),
        default = ""
    )

    val useSSL by boolean(
        title = Component.literal("Use SSL"),
        default = true
    )
}

    Using Nested Specs¶

    As a Single Field¶

    object General : CategorySpec(Component.literal("General"), "general") {
    val database by spec(
        title = Component.literal("Database Connection"),
        default = DatabaseConfig()
    )
}

    As a List¶

    object Servers : CategorySpec(Component.literal("Servers"), "servers") {
    val connections by specList(
        title = Component.literal("Server Connections"),
        factory = ::DatabaseConfig
    )
}

    As a Map¶

    object Databases : CategorySpec(Component.literal("Databases"), "databases") {
    val configs by specMap(
        title = Component.literal("Database Configurations"),
        factory = ::DatabaseConfig
    )
}

    Recursive Nested Specs¶

    Specs can reference themselves for tree-like structures:

    class FolderConfig : CategorySpec(Component.literal("Folder")) {
    val name by string(
        title = Component.literal("Name"),
        default = "New Folder"
    )

    val isExpanded by boolean(
        title = Component.literal("Expanded by Default"),
        default = false
    )

    // Self-reference for nested folders
    val subfolders by specList(
        title = Component.literal("Subfolders"),
        factory = ::FolderConfig
    )
}

    Complete Example: Permission System¶

    object Permissions : CategorySpec(Component.literal("Permissions"), "permissions") {

    // Define a permission node
    class PermissionNode : CategorySpec(Component.literal("Permission")) {
        val name by string(
            title = Component.literal("Permission Name"),
            default = "example.permission"
        )

        val description by string(
            title = Component.literal("Description"),
            default = "Permission description"
        )

        val defaultValue by boolean(
            title = Component.literal("Default Value"),
            default = false
        )

        // Nested permissions (for groups)
        val children by specList(
            title = Component.literal("Child Permissions"),
            factory = ::PermissionNode
        )
    }

    // Define a rank with permissions
    class RankConfig : CategorySpec(Component.literal("Rank")) {
        val name by string(
            title = Component.literal("Rank Name"),
            default = "Member"
        )

        val prefix by string(
            title = Component.literal("Chat Prefix"),
            default = "[Member]"
        )

        val weight by int(
            title = Component.literal("Weight"),
            default = 0
        )

        val permissions by specList(
            title = Component.literal("Permissions"),
            factory = ::PermissionNode
        )
    }

    // Configuration using the specs
    val ranks by specMap(
        title = Component.literal("Ranks"),
        factory = ::RankConfig
    )

    val defaultPermissions by specList(
        title = Component.literal("Default Permissions"),
        factory = ::PermissionNode
    )
}

    Accessing Nested Values¶

    // Single nested spec
val dbHost = Permissions.General.database.host
val dbPort = Permissions.General.database.port

// List of specs
for (server in Servers.connections) {
    println("Server: ${server.host}:${server.port}")
}

// Map of specs
val productionDb = Databases.configs["production"]
if (productionDb != null) {
    println("Production host: ${productionDb.host}")
}

// Recursive access
fun printFolder(folder: FolderConfig, indent: String = "") {
    println("$indent${folder.name}")
    for (subfolder in folder.subfolders) {
        printFolder(subfolder, "$indent  ")
    }
}

    UI Presentation¶

    Nested specs render as collapsible sections in the config GUI:

    • Single spec - Expandable card with all fields
    • Spec list - List of expandable items with add/remove
    • Spec map - Key-value pairs where values are expandable specs

    Serialization¶

    Nested specs are serialized recursively:

    {
    "general": {
        "database": {
            "host": "localhost",
            "port": 3306,
            "username": "root",
            "password": "",
            "useSSL": true
        }
    }
}

    Best Practices¶

    1. Keep nesting reasonable - Don't go deeper than 3-4 levels
    2. Use clear titles - Each nested spec should have a descriptive title
    3. Factory functions - Always provide a no-arg factory for lists/maps
    4. Validation - Implement validation in complex nested structures
    5. Defaults - Provide sensible defaults for all nested fields
